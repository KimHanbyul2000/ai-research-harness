# 스킬 목록 — 규칙을 도구에 심는 법

이 골격의 규칙은 문서로만 있으면 **읽히지 않는다.** AI 에이전트가 필요한 순간에 자동으로
꺼내 쓰게 만들어야 실제로 적용된다. 이 문서는 그 형태를 정한다.

> 이 저장소에는 스킬 구현이 들어 있지 않다. **어떻게 만들지를 정한 설계 문서**이며,
> 각 항목은 이 저장소의 규칙 문서 하나에 대응한다.

---

## 1. 규칙을 어디에 둘 것인가

판단 기준은 하나다 — **트리거 시점이 "항상"인가, 특정 순간인가.**

| 두는 곳 | 성격 | 여기 두는 것 |
|---|---|---|
| **`CLAUDE.md`** | 세션마다 자동으로 읽힌다. 짧아야 한다 | 포맷별 역할 · 게이트 4개 요약 · AI/사람 역할 분리 |
| **스킬** | 특정 순간에만 불려 온다. 길어도 된다 | 용어 대조 절차 · 오답노트 체크리스트 · 분석 시작 절차 · 렌더 확인 절차 |
| **도구 설정** | 사람이 승인하지 않으면 실행되지 않는다 | 되돌리기 비싼 명령 (`templates/claude_settings.example.json`) |
| **테스트** | 사람을 거치지 않고 잡는다 | 출력 테스트 · 렌더 프로브 |

**상주시키면 비싸고, 스킬로 빼면 안 불릴 수 있다.** 그래서 짧고 항상 적용되는 것만
`CLAUDE.md`에 두고, 절차가 있는 것은 전부 스킬로 뺀다.

> ⚠ **같은 규칙을 두 곳에 적지 않는다.** `CLAUDE.md`에는 한 줄 요약과 링크만 두고,
> 본문은 `docs/`에 둔다. 스킬은 그 문서를 본문으로 삼는다.

---

## 2. 트리거는 `description`이 정한다

스킬은 **설명문을 보고 불린다.** 본문이 아무리 좋아도 설명이 부실하면 영영 안 불린다.

```markdown
---
name: figure-design
description: >
  새 그림(정적 plot · figure · 애니메이션)을 설계하거나 만들기 전에 반드시 먼저 확인하는
  시각화 설계 원칙 스킬. "그림 만들어줘", "시각화해줘", "plot 추가해줘"처럼 새 시각화
  산출물을 요청받을 때, 또는 에이전트가 스스로 새 그림을 제안하려는 순간에 사용한다.
  기존 함수를 코드 변경 없이 그대로 재실행하는 경우에는 트리거하지 않는다.
---
```

세 가지가 들어가야 한다.

| | |
|---|---|
| **언제** | 작업의 어느 순간인가 ("만들기 **전**") |
| **어떤 말에** | 사람이 실제로 쓰는 표현을 그대로 나열한다 |
| **언제 아닌가** | ⭐ 이게 빠지면 엉뚱한 데서 불려 소음이 된다 |

---

## 3. 스킬 4종

각 스킬은 이 저장소의 문서 하나를 본문으로 삼는다. **문서가 먼저 있고 스킬이 나중이다.**

### ① `glossary-check` — 용어 대조

| | |
|---|---|
| **본문** | [`용어장부_규칙.md`](용어장부_규칙.md) · [`GLOSSARY.md`](../GLOSSARY.md) |
| **트리거** | `.md`를 새로 만들거나 크게 고친 직후. "용어 점검", "표준 용어 맞나" |
| **아닐 때** | 기존 문서의 오타·서식만 고치는 경우 |
| **하는 일** | 장부의 "쓰지 않는 표현"을 본문에서 훑어 걸린 곳을 **보고**한다. 장부에 없는 낯선 용어도 함께 올린다 |
| **사람이 하는 일** | 오용인지 인용인지 판단하고, 표준 용어를 **정한다** |
| **동봉 스크립트** | `grep` 한 겹이면 된다. 장부의 표를 읽어 표현 목록을 만들고 본문을 훑는다 |

> AI가 표준 용어를 스스로 정하게 두면 문제의 원인이 절차 안으로 들어온다.
> 스킬은 **검출과 보고**까지만 한다.

### ② `figure-design` — 오답노트 체크리스트

| | |
|---|---|
| **본문** | [`오답노트.md`](오답노트.md) |
| **트리거** | 새 그림을 설계·추가하기 전. 에이전트가 스스로 새 시각화를 만들려는 순간 |
| **아닐 때** | 기존 함수를 코드 변경 없이 재실행해 같은 그림을 다시 뽑는 경우 |
| **하는 일** | 패턴 목록을 통과시킨다. 특히 단일 출처 상수 · 배경 표시의 기준 · 반복 단위를 겹치지 않기 |
| **사람이 하는 일** | 그림의 **의도와 형식**을 정한다. 잘림·가림·색 의미를 눈으로 확인한다 |
| **동봉 스크립트** | 없음 — **판단 스킬**이다 (§5 참조) |

**패턴이 늘어나는 것이 정상이다.** 오류가 나면 이 스킬의 본문에 한 줄을 추가한다.

### ③ `analysis-start` — 게이트 1을 절차로

| | |
|---|---|
| **본문** | [`분석폴더_규칙.md`](분석폴더_규칙.md) · [`승인게이트.md`](승인게이트.md) |
| **트리거** | "분석 시작", "실험 돌려보자", 새 `out/` 폴더를 만들려는 순간 |
| **아닐 때** | 이미 있는 분석 폴더의 코드를 고치는 경우 |
| **하는 일** | `out/YYYYMMDD_<주제>/00_설계목표.md`를 서식대로 만들고, **"정한 것 \| 값 \| 이유" 표의 이유 칸이 비어 있으면 사람에게 묻는다.** 이 문서가 채워지기 전에는 `run.py`를 만들지 않는다 |
| **사람이 하는 일** | 목적과 판단 근거를 준다. 초안을 먼저 쓰는 쪽이 사람이다 |
| **동봉 스크립트** | `templates/` 복사 |

문서 서식 하나가 게이트가 된다 — 이유 칸을 채우려면 사람에게 물어야 하기 때문에,
별도의 차단 장치 없이 에이전트가 판단 지점에서 멈춘다.

### ④ `render-check` — 만든 그림을 실제로 연다

| | |
|---|---|
| **본문** | [`오답노트.md`](오답노트.md) 패턴 2 · 3 · 4 |
| **트리거** | 그림이나 `.html`·`.svg` 산출물을 만들거나 고친 직후 |
| **아닐 때** | 같은 코드로 대상만 바뀌는 연속 생성 — **최초 1회만** |
| **하는 일** | 아래 절차를 돈다 |

```bash
# 1. 구조부터 — 파싱이 깨지면 화면은 백지가 되는데 파일·HTTP 는 정상이다
python3 -c "import xml.dom.minidom; xml.dom.minidom.parse('<파일>.svg')"

# 2. 로컬 서버로 띄운다 (file:// 은 브라우저 자동화가 접근하지 못한다)
python3 -m http.server 8731

# 3. 열어서 본다 — 요소가 그려졌는가 · 글자가 잘리거나 가려지지 않았는가
# 4. 확인용 임시 파일은 지운다
```

**왜 스킬이어야 하는가:** 이 절차는 실제로 세 건을 잡았다 — 캔버스가 의도의 2배 높이로
늘어난 것, SVG 주석의 연속 하이픈으로 파일 전체가 백지가 된 것, CSS 클래스가
presentation attribute를 덮어 글자가 안 보인 것. **셋 다 파일 존재·종료 코드·타입 검사를
통과했다.** 사람이 매번 기억해서 돌 절차가 아니다.

---

## 4. 만드는 순서

1. **문서가 먼저.** `docs/`에 규칙이 없으면 스킬 본문이 없다. 스킬은 문서를 불러오는
   장치이지 규칙을 담는 곳이 아니다.
2. **트리거 문구를 쓴다.** §2의 세 가지. "언제 아닌가"를 빼먹지 않는다.
3. **검출을 붙인다.** 자동으로 잡을 수 있는 층이 있으면 스크립트를 동봉한다.
   없으면 판단 스킬로 둔다.
4. **안 불리는지 확인한다.** 만들고 나서 실제 작업 흐름에서 불려오는지 본다.
   안 불리면 본문이 아니라 **`description`을 고친다.**

---

## 5. 한계 — 먼저 알고 시작한다

| | |
|---|---|
| **판단 스킬에는 자동 검사가 없다** | `figure-design`이 그렇다. 체크리스트를 통과시키는 것은 에이전트의 판단이고, 통과했는지 확인할 방법이 없다. 그래서 **검출을 아래 층으로 내리는 것**이 목표다 |
| **스킬이 늘면 트리거가 충돌한다** | 비슷한 설명이 여럿이면 엉뚱한 게 불린다. 늘릴 때마다 "언제 아닌가"를 다시 손본다 |
| **본문이 길어지면 반영되지 않는다** | 항목이 20개를 넘으면 전부 반영되지 못한다. **검출이 코드로 내려간 항목은 본문에서 빼고** 검사 코드만 남긴다 — 문서가 아니라 코드가 규칙을 들고 있게 한다 |
| **스킬은 규칙을 지키게 하지 않는다** | 꺼내 오게 할 뿐이다. 되돌리기 비싼 것은 스킬이 아니라 **도구 설정**으로 막는다 |

## --- Notes ---

- 스킬로 만든다고 해서 규칙이 강해지지 않는다. 강해지는 것은 **꺼내 쓰는 비용이 싸지는
  것**이고, 이 골격이 작동하는 이유도 거기에 있다 — 오류 하나당 규칙 한 줄을 쓰는 값이
  싸다는 것.
- 반대로, 스킬 없이 `CLAUDE.md`만으로도 이 골격은 돈다. 스킬은 **`CLAUDE.md`가 길어져
  읽히지 않기 시작할 때** 꺼내는 수단이다. 처음부터 넷을 다 만들 필요는 없다.

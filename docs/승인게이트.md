# 승인 게이트 — 사람이 승인해야 다음 단계로 간다

## 문제 — AI는 멈추지 않는다

AI 에이전트에게 분석을 맡기면 **한 번 시켰는데 세 단계가 진행돼 있다.** 시뮬레이션을
돌리고, 그림을 그리고, 해석까지 써서 돌아온다. 빨라 보이지만 실제로 생기는 일은 이렇다.

| 일어나는 일 | 결과 |
|---|---|
| 중간에서 갈렸어야 할 판단이 **AI의 기본값으로 지나간다** | 그 선택을 한 줄도 검토하지 않았는데 결과가 나와 있다 |
| 앞 단계가 틀렸는데 뒤 단계가 이미 돌았다 | 되돌릴 작업이 한 단계가 아니라 세 단계다 |
| **맥락이 탈락한다** | "왜 이 값을 골랐나"가 대화에만 있고 파일에 없다. 다음 주엔 사라진다 |
| 무거운 실행이 **확인 없이** 돌아간다 | 연산 시간과 저장 용량을 쓰고 나서야 잘못된 대상이었음이 드러난다 |

되돌리는 비용이 실행 비용보다 크다. 그래서 **진행을 기본값으로 두지 않는다.**

---

## 네 개의 게이트

단계 사이마다 사람이 통과시켜야 한다. 게이트는 **비싼 것 앞에만** 둔다.

```
설계 ──[게이트 1]── 실행 ──[게이트 2]── 시각화 ──[게이트 3]── 확정 ──[게이트 4]── 추적
```

| | 게이트 | 통과 조건 | 없으면 생기는 일 |
|---|---|---|---|
| **1** | 설계 → 실행 | **`00_설계목표.md`가 먼저 존재한다** | 결과에 맞춰 목적이 재구성된다 |
| **2** | 실행 → 시각화 | 무거운 실행은 **점검 결과를 먼저 보고**한다 | 잘못된 대상으로 몇 시간을 쓴다 |
| **3** | 시각화 → 확정 | 사람이 **그림을 직접 보고** 승인한다 | 조용히 틀린 그림이 보고서로 간다 |
| **4** | 확정 → 추적 | [승격 관문 두 개](승격기준.md)를 통과한다 | 검토 안 된 코드가 라이브러리에 쌓인다 |

### 게이트 1 — 설계목표가 코드보다 먼저

`00_설계목표.md`가 없으면 `run.py`를 만들지 않는다. 서식과 이유는
[`분석폴더_규칙.md`](분석폴더_규칙.md).

**이게 게이트인 이유:** 문서를 먼저 쓰게 하면 AI가 **판단이 필요한 지점에서 멈춘다.**
"정한 것 | 값 | 이유" 표의 이유 칸을 채우려면 사람에게 물어야 하기 때문이다. 별도의
차단 장치 없이 문서 서식 하나가 게이트가 된다.

### 게이트 2 — 무거운 실행은 "지정 → 점검 → 확정"

돌리기 전에 **점검 전용 모드**로 먼저 돌린다.

```bash
python run.py --범위 <지정> --check-only   # ① 점검만 하고 멈춘다
python run.py --범위 <지정>                # ② 승인 후 실제 실행
```

`--check-only`가 보고하는 것:

- 지정한 범위에 **데이터가 실제로 있는가**
- 경계가 **봐야 할 대상을 잘라내지 않는가**
- 기준으로 삼을 사례가 **범위 안에 들어 있는가**
- 산출물 **용량이 얼마인가**

> 실제 효과: 범위 지정이 틀렸을 때 **빈 폴더 하나만 남기고 죽던 것**이, 실행 전에
> "아무것도 만들지 않는다"고 알리고 올바른 명령을 함께 보고하도록 바뀌었다.

**`--check-only`를 기본값으로 두지 않는다.** 기본이 점검이면 사람이 습관적으로
`--check-only`를 빼게 되고, 그러면 게이트가 아니라 타자 한 번이 된다. 점검은 **명시적으로
요청**하고, 그 출력을 보고받은 뒤 확정한다.

### 게이트 3 — 그림은 사람이 보고 승인한다

**사람이 그림을 확인하지 않은 상태에서 다음 분석을 시작하지 않는다.**

AI는 그림이 틀린 것을 모른다. 숫자가 맞고 코드가 돌았으면 성공으로 보고한다. 그런데
시각화 오류는 **숫자가 맞는 채로 틀린다** — 실제 사례는 [`오답노트.md`](오답노트.md)에 있다.

- 그림의 **의도와 형식은 사람이 정한다.** AI가 그림 종류를 임의로 늘리지 않는다.
- AI가 새 그림을 **제안**하려는 순간도 게이트다. "이런 것도 보여드릴까요"로 추가하지 않고,
  왜 필요한지 설명하고 판단을 받는다.

### 게이트 4 — 승격

[`승격기준.md`](승격기준.md) 참조. AI가 만든 코드가 검토 없이 라이브러리에 눌러앉는 것을
막는 지점이다.

## 도구 쪽 장치

문서 규칙만으로는 새지 않는다. **되돌리기 비싼 명령**은 도구 설정에서 확인을 강제한다.

`templates/claude_settings.example.json` 참조 — 요지는 셋이다.

| | |
|---|---|
| **묻는다** (`ask`) | `git commit` · `git push` · `git reset --hard` · `git clean` — 되돌리기 비싼 것 |
| **막는다** (`deny`) | `sudo` · 광범위 삭제 · 비밀 파일 읽기 |
| **통과시킨다** | 파일 읽기·쓰기·검색 — 매번 물으면 게이트가 소음이 된다 |

> **게이트를 늘리면 게이트가 죽는다.** 전부 물으면 사람이 전부 승인한다. 확인은 **되돌리기
> 비싼 곳에만** 둔다. 위 표에서 `ask`가 여섯 줄뿐인 것이 그래서다.

## Human-in-the-Loop은 '느리게 하는 것'이 아니다

| 오해 | 실제 |
|---|---|
| AI를 덜 쓰게 된다 | 쓰는 양은 같다. **어디에 쓰는지**가 바뀐다 |
| 매 단계 승인하느라 느려진다 | 게이트는 4개뿐이다. 그 사이는 자유 |
| 자동화를 포기하는 것 | 자동화하는 것이 실행에서 **기록·검증**으로 옮겨간 것 |

사람이 유지하는 것은 **판단**이고, AI가 맡는 것은 그 판단이 **기록·재현·검증되게 만드는
일**이다. 게이트는 판단이 일어나야 할 지점에 사람을 세우는 장치다.

## --- Notes ---

- 게이트 1과 3이 가장 값이 싸다(문서 서식 하나, 확인 습관 하나). 도입한다면 여기부터.
- 게이트 2는 실행이 무거운 분야에서만 필요하다. 몇 초에 끝나는 분석이면 없어도 된다 —
  되돌리는 비용이 실행 비용보다 작기 때문이다.
- 게이트의 개수가 아니라 **위치**가 중요하다. 비싼 것 앞에 없으면 게이트가 없는 것과 같다.

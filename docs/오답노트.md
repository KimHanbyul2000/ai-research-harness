# 오답노트 — 시각화 오류 패턴

## 왜 오답노트인가

> **AI가 만든 시각화는 조용히 틀린다. 숫자는 맞는데 화면이 틀리고, 테스트는 통과한다.**

코드 오류는 멈춘다. 계산 오류는 검산으로 걸린다. 그런데 시각화 오류는 **정상적으로 실행되고,
그럴듯한 그림이 나오고, 단위 검사를 통과한다.** 걸리는 시점은 그 그림을 들고 발표하러 간
자리다.

그래서 같은 유형이 반복된다. 매번 고치고 넘어가면 다음 그림에서 또 나온다. **고치는 것으로
끝내지 않고 패턴으로 적립한다.**

### 오류 하나당 규칙 한 줄

이 골격이 작동하는 이유는 도구가 좋아서가 아니라 **오류 하나당 규칙 한 줄을 쓰는 비용이
싸서**다. 규칙이 `.md`에 있고 AI가 세션마다 그걸 읽으므로, 한 줄을 추가하는 순간 다음부터
자동으로 적용된다.

| | |
|---|---|
| **기록하는 것** | 두 번 이상 났거나, 한 번인데 되돌리기 비쌌던 것 |
| **기록하지 않는 것** | 일회성 오타, 그 데이터에서만 생기는 문제 |

---

## 기록 서식

각 패턴은 네 칸이다. **"왜 안 걸렸나" 칸이 핵심이다** — 그 칸이 검출 수단을 알려준다.

```markdown
### N. <한 줄 증상>  (YYYY-MM-DD)

- **무슨 일이:** 실제로 일어난 일. 날짜와 함께.
- **왜 안 걸렸나:** 어떤 검사를 통과했는가. ← 여기가 다음 검사를 설계하는 자리
- **규칙:** 다음부터 무엇을 하는가. 한 줄.
- **검출:** 자동으로 잡을 수 있는가. 없으면 '사람 확인'.
```

## 패턴 목록

> 아래는 실제로 난 사고를 도메인 내용을 빼고 기록한 것이다. 날짜는 실제 날짜다.
> 패턴 1·5·7은 [`demo/index.html`](../demo/index.html) 탭 ①에서 **틀린 판 / 고친 판**으로
> 직접 바꿔 볼 수 있다.

### 1. 그림이 자기 자신과 모순된다 (2026-08-10)

- **무슨 일이:** 배경 음영으로 "이 구간은 사건 없음"을 칠했는데, **그 칠한 자리 위에 사건
  점이 찍혀 있었다.** 음영 기준과 데이터 기준이 서로 다른 값을 쓰고 있었다.
- **왜 안 걸렸나:** 음영과 데이터가 **각각은 맞았다.** 둘을 대조하는 검사가 없었다.
  값 범위 검사·단위 검사 전부 통과.
- **규칙:** 배경 표시의 기준값은 **그림이 그리는 데이터에서 뽑는다.** 별도로 적어두지
  않는다. 별도로 적어야 하면 실측값으로 고정하고 근거를 코드에 남긴다.
- **검출:** ✅ 자동 — 음영 구간과 데이터 점의 교집합이 비어 있는지 단언한다.

> 이 유형이 가장 위험하다. **그림 한 장 안에서 두 요소가 서로 다른 진실을 말하는데, 각
> 요소는 자기 검사를 통과한다.**

### 2. 아무것도 안 그려진 화면이 성공으로 보고된다 (2026-09-07)

- **무슨 일이:** 생성이 정상 종료되고 파일도 만들어졌는데 **열어보니 백지**였다.
- **왜 안 걸렸나:** 파일 존재·크기 검사를 통과했다. 빈 캔버스도 파일 크기는 나온다.
- **규칙:** 화면에 **무엇이 몇 개 그려졌는지**를 검사한다. 파일이 생겼는지가 아니라.
- **검출:** ✅ 자동 — 렌더 후 요소 개수를 세어 0이 아님을 단언한다(아래 "렌더 프로브").

### 3. 글자가 잘리거나 가려진다 (2026-09-15, 하루에 5건)

- **무슨 일이:** 하루 작업에서 다섯 가지가 한꺼번에 걸렸다 — 긴 제목이 그림 폭을 넘음 ·
  항목 다섯 개짜리 범례가 한 줄로 넘침 · 구분 테두리 선이 축 글자를 가림 · 대상 표시
  기호가 수치 글자와 겹침 · 수학 기호가 폰트에서 깨짐.
- **왜 안 걸렸나:** **전부 값은 맞다.** 위치와 크기의 문제이고, 그건 실제 렌더링 결과를
  보기 전엔 알 수 없다.
- **규칙:** 그림을 만들면 **직접 열어서 본다.** 제목·부제·패널 제목·축 이름·범례·주석이
  잘리거나 가려지지 않았는지. 같은 코드로 대상만 바뀌는 연속 생성은 **최초 1회만** 본다.
  코드를 고쳐 다시 그렸으면 다시 본다.
- **고칠 때:** 긴 문구는 줄을 나누거나 부제로 내린다. 여백은 **비율이 아니라 절대 단위**로
  잡는다 — 비율로 잡으면 폭이 다른 그림에서 여백이 달라진다.
- **검출:** ⚠ 사람 확인. 자동화가 가장 어려운 층이다.

### 4. 폰트가 깨진 채로 저장된다 (상시)

- **무슨 일이:** 한글·특수문자·수학 기호가 네모로 나온다. 실행 환경이 바뀌면 재발한다.
- **왜 안 걸렸나:** 문자열은 맞다. **렌더링 단계에서만** 깨진다.
- **규칙:** 폰트 설정을 **단일 함수**로 만들고 모든 시각화 파일이 그것을 호출한다.
  운영체제 전용 폰트 이름을 코드에 직접 쓰지 않는다.
- **검출:** ✅ 자동 — 시각화 파일이 그 함수를 호출하는지 검사한다.

### 5. 색이 정반대로 칠해진다 (2026-09-16)

- **무슨 일이:** 개념도에서 두 범주의 색이 **서로 뒤바뀌어** 있었다. 게다가 같은 색
  상수를 "값의 부호"에도 재사용해, 범주와 무관한 것이 범주 색으로 칠해졌다.
- **왜 안 걸렸나:** 색은 검사 대상이 아니었다. 그림은 정상적으로 나왔다.
- **규칙:** 범주별 색은 **고정하고 단일 출처 상수로 둔다.** 그림마다 다시 고르지 않는다.
  **범주가 아닌 것에는 그 색을 쓰지 않는다** — 값의 부호, 계산의 조각, 조건 구분 같은 것을
  범주 색으로 칠하면 독자가 범주로 읽는다. 그런 구분은 채움 여부·선 모양·위치처럼 **색이
  아닌 수단**으로 가른다.
- **검출:** ⚠ 사람 확인. 단 **고친 비용은 낮다** — 상수 두 줄을 바꿔 그림 10장을 다시
  냈다. 단일 출처가 아니었으면 10곳을 고쳐야 했다.

### 6. 뭉개는 폭을 안 적어서 다른 값과 섞인다 (2026-07-20)

- **무슨 일이:** 스무딩 폭·구간 폭에 따라 **값 자체가 크게 달라지는데** 그림에 그 값이
  없었다. 다른 폭으로 계산한 값과 나란히 비교하고 있었다.
- **왜 안 걸렸나:** 각 그림은 자기 폭에서 맞다. **비교할 때만** 틀린다.
- **규칙:** 뭉개는 폭이 결과를 바꾸는 그림은 **그 값을 제목이나 부제에 적는다.**
- **검출:** ✅ 자동 — 해당 함수군이 파라미터를 제목 문자열에 넣는지 검사한다.

### 7. 여러 판을 겹쳐서 구분이 지워진다 (2026-09-15)

- **무슨 일이:** 반복 단위 여러 개를 한 줄에 겹쳐 그렸더니, **"한 번만 일어난 것"과
  "매번 일어난 것"이 같은 그림**이 됐다.
- **왜 안 걸렸나:** 겹친 그림도 정보 손실 없이 그려진다. 손실은 **독자 쪽에서** 생긴다.
- **규칙:** 반복 단위는 **나눠서 그리는 것이 기본**이다. 겹치는 판은 요청이 있을 때만.
  세로축을 반복 단위로 쌓는 형태를 우선한다.
- **검출:** ⚠ 사람 확인 — 설계 단계 판단이다.

### 8. 격자 배치가 두 구조를 섞어 보이게 한다 (2026-08-10)

- **무슨 일이:** 여러 패널을 **번호순 정사각 격자**로 깔았더니, 행 중간에서 범주가 끊겨
  "행을 내려가면 변하는 것"과 "같은 범주 안에서 갈리는 것"이 섞여 보였다.
- **왜 안 걸렸나:** 격자 배치는 값과 무관하다. 그림은 전부 맞다.
- **규칙:** 격자의 **행과 열에 각각 의미를 준다.** 행 = 범주, 열 = 그 범주 안의 변이.
  번호순으로 깔지 않는다. 행 길이가 고르지 않으면 그대로 두고 남는 칸은 범례로 쓴다.
- **효과:** 재배치하고 나서야 **행 안의 흩어짐이 행 사이 이동폭보다 크다**는 것이 눈에
  들어왔다. 배치가 바뀌자 없던 관찰이 생겼다.
- **검출:** ✅ 부분 자동 — 행 구성이 의도한 길이와 맞는지 `assert`로 확인한다.

### 9. 같은 범례가 패널마다 반복된다 (2026-07-15)

- **무슨 일이:** 여덟 패널에 **같은 범례가 여덟 번** 들어갔다.
- **규칙:** 같은 색-라벨 매핑이 여러 패널에 반복되면 **그림 전체에 하나만** 둔다.
- **검출:** ⚠ 사람 확인.

### 10. 라이브러리 기본값을 뒤집어 옛 그림이 조용히 바뀐다 (2026-09-20)

- **무슨 일이:** 공용 함수의 기본 동작을 바꿨는데, 그 인자를 **명시하지 않고 부르던
  기존 호출자들의 출력이 함께 바뀌었다.** 같은 기본값이 두 번 뒤집힌 적도 있다.
- **왜 안 걸렸나:** 고친 것은 한 파일이고 영향은 여러 파일에 퍼진다. 테스트가 그 인자를
  명시하고 있으면 테스트는 통과한다.
- **규칙:** 기본값을 바꾸기 전에 **기존 호출자가 그 인자를 명시하는지 확인한다**
  (명시 = 안 바뀜). 안 하고 있으면 바꾸기 전에 알린다.
- **검출:** ✅ 자동 — 호출부를 검색해 명시 여부를 센다.

## 검출은 네 층이다

패턴 목록이 길어져도 사람이 매번 체크리스트를 도는 것은 지속되지 않는다. **가능한 층부터
자동으로 내린다.**

| 층 | 무엇을 잡나 | 비용 |
|---|---|---|
| **1. 단일 출처 상수** | 색·폰트·배치 — 값이 한 곳에만 있으면 틀릴 자리가 한 곳뿐 | 0 (구조) |
| **2. 그리는 코드와 계산 코드 분리** | 계산을 고치다 그림이 바뀌는 것 | 0 (구조) |
| **3. 출력 테스트** | 백지 · 요소 개수 · 배치 구조 · 제목에 파라미터 포함 여부 | 낮음 |
| **4. 사람 확인** | 잘림 · 가림 · 색 의미 · 그림의 의도 | 높음 |

**4층으로 올라올 것을 줄이는 게 목표다.** 새 패턴이 생기면 먼저 묻는다 — "이건 1~3층으로
내릴 수 있나?"

### 렌더 프로브 — 브라우저 산출물에도 테스트를 건다

`.html` 산출물은 `.png`보다 검사하기 쉽다. **실제로 렌더한 뒤 화면 상태를 읽을 수 있기
때문이다.**

```javascript
// tests/render_probe.js — 렌더 후 상태를 읽어 단언한다
//   · 캔버스에 그려진 요소 개수가 0이 아닌가      (패턴 2)
//   · 범례 항목 수가 데이터 계열 수와 일치하는가   (패턴 9)
//   · 범주 색이 단일 출처 상수와 일치하는가        (패턴 5)
```

> **문자열 안에 있는 코드는 문법 검사가 닿지 않는다.** `.html`을 만드는 스크립트는 보통
> JavaScript를 **문자열로** 들고 있어서, 그 안의 오타는 실행 전까지 아무 검사에도 안
> 걸린다. 렌더 프로브가 그 층을 연다.

## 규칙이 바뀌었을 때 — 옛 그림을 일괄로 다시 굽지 않는다

오답노트에 항목이 추가되면 **기존 그림 전부가 그 기준에 미달**한다. 그렇다고 전부 다시
굽지 않는다.

- **이미 있는 그림은 그대로 둔다.** 다음에 그 함수를 실제로 손댈 때 같이 고친다.
  규칙이 바뀌었다는 사실 자체는 다시 굽는 근거가 아니다.
- 일괄 재생성은 **사람이 "전체 수정"을 지시할 때만.**
- 다시 구운 판은 옛 판을 **덮어쓰지 않는다.** 파일명 끝에 규칙 날짜를 붙여 나란히 둔다
  (`..._규칙20260920.png`). 어느 규칙 아래 만든 그림인지가 파일명에 남는다.

> 이유: 옛 그림은 **그때의 기준으로 읽혀야 맞는** 기록이다. 소급해서 바꾸면 그 시점의
> 판단 근거가 사라진다.

## --- Notes ---

- 이 문서는 **AI가 세션마다 읽는 파일**이어야 의미가 있다. 사람만 보는 체크리스트는
  지켜지지 않는다.
- 패턴 1·2·5가 반복 비중이 가장 높았다. 도입한다면 이 셋의 검사부터.
- 패턴이 20개를 넘으면 AI가 전부를 반영하지 못한다. 그때는 **1~3층으로 내려간 항목을
  목록에서 빼고** 검사 코드로만 남긴다 — 문서가 아니라 코드가 규칙을 들고 있게 한다.

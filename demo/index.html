ai-research-harness — .html이 검증 단계의 도구라는 것과, 시각화 오류가 검사를 통과한 채로 틀린다는 것을 조작으로 확인하는 페이지.

값·조건명·단위는 전부 가상이다. 고정 시드로 페이지 안에서 생성하며 외부 통신이 없다. 설계 의도는 demo/00_설계목표.md에 있다.

시각화 오류는 검사를 통과한 채로 틀린다

각 패턴에서 틀린 판 / 고친 판을 바꿔가며 본다. 그림보다 오른쪽 검사 결과 칸을 볼 것 — 틀린 판에서도 값·단위 검사는 통과한다. 실패는 대조 검사에서만 난다.

패턴 1 — 그림이 자기 자신과 모순된다 (2026-08-10)

회색 띠 = "이 구간엔 사건 없음"이라고 칠한 음영. 세로선 = 실제 사건. 틀린 판에서는 음영 위에 사건이 찍혀 있다 — 음영 기준과 데이터가 서로 다른 값을 쓰고 있었다.

왜 안 걸렸나: 음영과 데이터가 각각은 맞다. 둘을 대조하는 검사가 없었다.

규칙: 배경 표시의 기준값은 그림이 그리는 데이터에서 뽑는다. 따로 적어두지 않는다.

패턴 5 — 색이 정반대로 칠해진다 (2026-09-16)

단일 출처 상수는 범주 A = 붉은색, 범주 B = 청색. 틀린 판에서는 둘이 뒤바뀌었고, 게다가 범주가 아닌 것(값의 부호)에 같은 두 색을 재사용해 독자가 범주로 읽게 됐다.

왜 안 걸렸나: 색은 검사 대상이 아니었다. 그림은 정상적으로 나왔다.

고친 비용: 상수 두 줄. 단일 출처가 아니었으면 쓰인 곳 전부를 고쳐야 했다.

패턴 7 — 여러 판을 겹쳐서 구분이 지워진다 (2026-09-15)

두 대상의 10주기 기록. 겹친 판에서는 둘이 거의 같아 보인다. 나눈 판(세로축 = 주기)에서 보면 하나는 1주기에만, 다른 하나는 매 주기 사건이 있다.

왜 안 걸렸나: 겹친 그림도 정보 손실 없이 그려진다. 손실은 독자 쪽에서 생긴다.

검출: 자동화 안 됨 — 설계 단계 판단이다. 그래서 규칙으로 고정한다: 반복 단위는 나눠 그리는 것이 기본.

이 네 동작이 곧 검증이다

동작 답하는 질문 .png이면
조건 켜고 끄기이 차이가 조건 때문인가조합마다 한 장씩 미리 굽는다
구간 확대뭉쳐 보이는 저 안은 어떤가해상도에 막힌다
값 읽기저 점이 정확히 몇인가읽을 수 없다
구간 통계눈에 보이는 차이가 수치로도 나오나따로 계산해야 한다

그래서 .html은 결론이 아니다. 여기서 본 것은 .md(해석)나 .png(확정)로 옮겨 적기 전까지 기록이 아니다. 뷰어를 열어 확인하고 끝내면 다음 주에 같은 것을 다시 연다.

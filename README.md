# ai-research-harness

**연구자가 주도권을 유지하는 AI 작업 골격.**
파일 포맷별 역할 분리 · 용어 장부 · 승인 게이트 · 오답노트 네 가지로 이루어져 있다.

---

## 무엇을 푸는가

> **코드는 틀리면 멈추지만, 분석은 틀려도 숫자가 나온다.**

AI 도구를 쓰면 분석이 빨라진다. 그런데 분석의 실패 양상은 정지가 아니라 **조용히 틀린 채로
계속 가는 것**이다. 빨라질수록 이 위험이 커진다. 구체적으로 네 가지가 일어난다.

| 문제 | 실제로 무슨 일이 생기나 | 대응 |
|---|---|---|
| **AI가 다음 단계까지 진행해버린다** | 한 번 시켰는데 세 단계가 돌아 있다. 중간에서 갈렸어야 할 판단이 AI 기본값으로 지나가고, **"왜 이 값인가"가 대화에만 남고 파일엔 없다** | [승인 게이트](docs/승인게이트.md) |
| **용어를 지어낸다** | 그럴듯한데 그 분야에서 안 쓰는 말. 또는 같은 말을 문서마다 다른 뜻으로 씀. **검산이 안 된다** | [용어 장부](GLOSSARY.md) |
| **시각화가 조용히 틀린다** | 숫자는 맞는데 화면이 틀리고, 테스트는 통과한다. 걸리는 시점은 그 그림을 들고 발표하러 간 자리다 | [오답노트](docs/오답노트.md) |
| **산출물 형태가 매번 다르다** | 어떤 날은 긴 문서, 어떤 날은 그림. 형태가 흔들리면 **무엇을 검토해야 하는지가 흔들린다** | [포맷별 역할](docs/포맷별_역할.md) |

대응 방향은 도구를 더 쓰는 쪽이 아니다. **판단은 사람이 유지하되, 그 판단이 기록·재현·검증
되도록 AI가 강제하게** 만드는 쪽이다.

## 네 개의 장치

### 1. 파일 포맷을 지시로 쓴다 → [`docs/포맷별_역할.md`](docs/포맷별_역할.md)

포맷마다 할 일과 검토 방식을 고정한다. "이건 `.html`로 낸다"는 한마디가 **"동적으로 확인할
단계이고 아직 결론이 아니다"**까지 함께 전달한다.

| 포맷 | 단계 | 역할 | 검토 |
|---|---|---|---|
| `.md` | 전 단계 | 규칙 · 설계 · 해석 · 용어 | 읽는다. 용어는 장부 대조 후 확정 |
| `.svg` | 설계 | 구조 · 개념 · 관계 (**값 없음**) | 본다 |
| `.html` | 검증 | 데이터 **동적 탐색** | 조작한다. 아직 결론 아님 |
| `.png` | 결론 | 확정된 결과 | **승인한다** |

`.md` → `.svg` → `.html` → `.png` 순서로 간다. 거꾸로 가지 않는다 — `.png`부터 만들면
그 그림에 맞는 해석이 나중에 붙는다. 전부 표준 포맷이라 **도구를 새로 도입하지 않는다.**

### 2. 용어는 장부와 대조한 뒤 확정한다 → [`GLOSSARY.md`](GLOSSARY.md)

AI가 만든 문서에서 가장 자주 틀리는 것은 숫자가 아니라 **용어**다. 그리고 용어 오류는
검산이 안 된다.

```
AI가 .md 생성 → GLOSSARY.md 대조 → 표준 용어로 확정
                      ↓
              장부에 없는 말은 전부 사람 앞에 올라온다
```

생성 시점에 못 만들게 하는 것은 불가능하다(AI는 자기가 만든 말인지 모른다). 그래서 이건
**통제 장치가 아니라 통과 지점**이다. 가장 비싼 오류는 "없는 말"이 아니라 **"있는 말이 두
뜻으로 쓰이는 것"**이라, 장부에 "혼동 주의" 절을 따로 둔다.

→ 절차: [`docs/용어장부_규칙.md`](docs/용어장부_규칙.md)

### 3. 사람이 승인해야 다음 단계로 간다 → [`docs/승인게이트.md`](docs/승인게이트.md)

```
설계 ──[1]── 실행 ──[2]── 시각화 ──[3]── 확정 ──[4]── 추적
```

| | 게이트 | 통과 조건 |
|---|---|---|
| 1 | 설계 → 실행 | `00_설계목표.md`가 **코드보다 먼저** 존재한다 |
| 2 | 실행 → 시각화 | 무거운 실행은 `--check-only`로 **점검 결과를 먼저 보고** |
| 3 | 시각화 → 확정 | 사람이 **그림을 직접 보고** 승인한다 |
| 4 | 확정 → 추적 | [승격 관문 두 개](docs/승격기준.md)를 통과한다 |

**게이트를 늘리면 게이트가 죽는다.** 전부 물으면 사람이 전부 승인한다. 확인은 되돌리기
비싼 곳에만 넷 둔다.

### 4. 오류 하나당 규칙 한 줄 → [`docs/오답노트.md`](docs/오답노트.md)

시각화 오류는 **정상 실행되고, 그럴듯한 그림이 나오고, 단위 검사를 통과한다.** 그래서
고치고 넘어가면 다음 그림에서 또 나온다. 패턴으로 적립한다.

실제로 난 사고 10종이 날짜와 함께 들어 있다 — 그림이 자기 자신과 모순된 경우, 백지 화면이
성공으로 보고된 경우, 색이 정반대로 칠해진 경우 등. 각 항목에 **"왜 안 걸렸나"**를 적는데,
그 칸이 다음 검사를 설계하는 자리다.

검출은 네 층이고, **가능한 층부터 자동으로 내리는 것**이 목표다.

| 층 | 무엇을 잡나 | 비용 |
|---|---|---|
| 1. 단일 출처 상수 | 색 · 폰트 · 배치 | 0 (구조) |
| 2. 그리는 코드와 계산 코드 분리 | 계산을 고치다 그림이 바뀌는 것 | 0 (구조) |
| 3. 출력 테스트 · 렌더 프로브 | 백지 · 요소 개수 · 배치 구조 | 낮음 |
| 4. 사람 확인 | 잘림 · 가림 · 색 의미 · 그림의 의도 | 높음 |

## 전제 — 데이터를 우리가 만든다

이 골격이 나온 워크플로가 다루는 것은 **측정값이 아니라 시뮬레이션이 만든 값**이다.
이게 앞의 네 장치보다 먼저 오는 조건이라 따로 적는다.

생성 규칙이 전부 코드에 있으므로, 어떤 값이 왜 그렇게 나왔는지가 **원리까지 거슬러
올라간다.** 그래서 AI에게 분석을 맡길 때 표면의 상관에서 멈추지 않고 **가장 바닥의
기전을 짚게** 할 수 있다 — "이 값이 왜 이런가"를 물으면 생성 코드까지 따라가 답이 나온다.
[재현 검산](docs/분석폴더_규칙.md)이 성립하는 것도 같은 이유다.

**실측 데이터에서는 이게 성립하지 않는다.** 측정값의 원인은 데이터 바깥에 있어서, 아무리
파고들어도 "이런 경향이 있다"에서 멈춘다. 이식할 때 이 차이를 먼저 확인해야 한다.

| | 생성 데이터 | 실측 데이터 |
|---|---|---|
| 원인 추적 | **생성 코드까지 내려간다** | 데이터 밖에 있어 불가 |
| 재현 검산 | 같은 시드 → 같은 값 | 같은 입력에 같은 출력까지만 |
| AI에게 시킬 수 있는 질문 | "왜 이 값인가" | "어떤 경향이 있나" |
| 이 골격에서 그대로 쓰이는 부분 | 전부 | 포맷 규칙 · 용어 장부 · 승인 게이트 · 오답노트 |

네 장치 자체는 데이터 출처와 무관하게 이식된다. 달라지는 것은 **AI에게 던질 수 있는
질문의 깊이**다.

## 이 넷이 작동하는 이유

**규칙을 `.md`에 두고 AI가 세션마다 읽게 하기 때문에, 규칙 한 줄을 추가하는 비용이 거의
0이다.** 오류 발견 → 규칙 작성 → 자동 적용의 고리가 한 사람 안에서 닫힌다.

이게 **전제 조건**이기도 하다. 그 한 줄을 쓸 사람이 없으면 고리가 닫히지 않는다.

## 데모 — 주장을 조작으로 확인한다

[`demo/index.html`](demo/index.html) 을 브라우저로 연다. 빌드·설치·통신 없이 파일 하나로 돈다.

| 탭 | 보여주는 것 |
|---|---|
| **① 오답노트 실연** | 패턴 1·5·7을 **틀린 판 / 고친 판**으로 토글한다. 틀린 판에서도 값·단위 검사는 ✓로 통과하고, 실패는 **대조 검사에서만** 난다 — "조용히 틀린다"가 이 대비다 |
| **② 데이터 탐색** | 조건 켜고 끄기 · 드래그로 구간 확대 · 호버로 값 읽기 · 구간 통계. `.png`로 답할 수 없는 네 질문 |

같은 폴더의 [`개념도_포맷흐름.svg`](demo/개념도_포맷흐름.svg)는 `.svg`의 역할을 보여주는
예다 — 구조만 담고 값은 담지 않는다. 설계 의도는 [`demo/00_설계목표.md`](demo/00_설계목표.md)에
있다. **이 폴더 자체가 게이트 1을 지킨 예다**(설계목표가 코드보다 먼저 존재한다).

> 데모의 값은 전부 가상이다. 실제 연구 데이터는 들어 있지 않다.

## 도입하기

```bash
git clone https://github.com/KimHanbyul2000/ai-research-harness
```

**최소 단위 — 두 가지만 먼저 시작한다.**

1. 분석 폴더마다 **`00_설계목표.md`를 실행 전에** 쓴다 (게이트 1).
2. AI가 만든 `.md`를 **`GLOSSARY.md`와 대조**한 뒤 확정한다.

나머지(오답노트 · 렌더 테스트 · 포맷 규칙 · git 3단 추적)는 이 둘이 돌아간 뒤에 붙인다.
한 번에 전부 도입하면 규칙이 지켜지지 않고, **지켜지지 않는 규칙은 없는 것보다 나쁘다.**

**전제 조건 3가지**

- 프로젝트 규칙이 **지속되는 파일**로 남는 AI 도구 (세션마다 자동으로 읽히는 것)
- 원본 데이터 보관 — 재현 검산이 성립하려면 다시 돌릴 수 있어야 한다
- **규칙을 쓸 담당자 한 명** — 오류 발견 → 규칙 작성 → 자동 적용의 고리가 닫혀야 한다

## 구성

```
├── CLAUDE.md                     AI 에이전트가 세션마다 읽는 규칙서 (골격)
├── GLOSSARY.md                   용어 장부 — 표준 용어 · 혼동 주의 · 표기 규약
├── docs/
│   ├── 포맷별_역할.md             .md · .svg · .html · .png 의 역할과 순서
│   ├── 용어장부_규칙.md           생성 직후 대조 절차, 용어가 바뀌었을 때
│   ├── 승인게이트.md              게이트 4개 + 도구 쪽 장치
│   ├── 오답노트.md                시각화 오류 패턴 10종 + 검출 4층
│   ├── 분석폴더_규칙.md           3종 세트 · 탈락 사유 · 커버리지 감사 · 재현 assert
│   ├── 승격기준.md                git 3단 추적의 승격 관문 (보조)
│   └── skill_list.md             위 규칙을 에이전트 스킬로 심는 법 (설계)
├── templates/                    빈 서식 (00 · 01 · run.py · 도구 설정 예시)
├── examples/                     채워진 예시 1건
├── demo/                         브라우저로 여는 데모 (뷰어 · 개념도 · 설계목표)
├── .gitignore                    3단 추적의 실물
└── lib/                          승격 통과분이 오는 곳 (비어 있음)
```

### 보조 — 분석 기록과 git 3단 추적

위 네 장치는 **AI와 사람 사이의 규율**이고, 아래 둘은 **그 결과물을 다루는 규율**이다.
먼저 도입할 필요는 없다.

- [`docs/분석폴더_규칙.md`](docs/분석폴더_규칙.md) — 분석 하나 = 폴더 하나, 세 파일이 항상
  같이 있다. 결과해석에는 통과분만이 아니라 **탈락 사유를 단계별로** 남기고, 기준이
  바뀌었으면 **어디까지 재적용했는지 커버리지 표**를 남기며, 재분석은 **옛 기준으로 이전
  결론이 재현되는지 `assert`**로 막는다.
- [`docs/승격기준.md`](docs/승격기준.md) — git 추적을 3단(`out/` 비추적 → `bootstrap/`
  스냅샷 → `lib/` 라이브러리)으로 나눠, AI가 만든 코드가 검토 없이 라이브러리에 눌러앉는
  것을 막는다. 승격 관문은 **의존성 없음 + 두 번째 사용자 있음** 둘 다 만족해야 한다.

---

## 이 저장소에 없는 것

- **도메인 코드.** 분석 로직은 각자 분야의 것이다. `lib/`는 비어 있다.
- **실행 가능한 파이프라인.** 이건 프레임워크가 아니라 **작업 방식의 골격**이다.
  `examples/`의 코드도 모양을 보여주기 위한 것으로, 그대로 돌아가지 않는다.
- **실제 연구 데이터.** 예시의 값과 용어는 전부 가상이다.

## 배경

개인 연구 워크플로(스파이킹 신경망 시뮬레이션의 데이터 분석, 2026년 5월~)에서 도메인에
의존하지 않는 부분만 추출한 것이다. 규칙은 대부분 **실제로 사고가 난 뒤에** 추가됐고,
그 계기를 각 문서에 날짜와 함께 남겼다. 이유를 모르는 규칙은 나중에 지워지기 때문이다.
